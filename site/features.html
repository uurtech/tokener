Features

Everything you need to run Claude Code at team scale.

Pool your keys, measure first, then pull the cost levers one at a time, without changing how developers work.

Key pool v0.2 · extended in v0.3

Many upstream keys, one endpoint. Developers keep a single ANTHROPIC_BASE_URL, and the gateway decides which key serves each request.

🔁

Four rotation strategies

Per session (default) spreads new sessions and keeps each one on its key so the prompt cache stays warm. Also round-robin, fill-first by priority, and least-used.

🛟

Invisible failover

429, 529, 5xx, 401/403 and out-of-credit answers trigger a retry of the same request on the next key, before anything is streamed. Request errors such as a bad body are never retried.

📉

Proactive switching

Anthropic's anthropic-ratelimit-*-remaining headers are tracked per key. Under the threshold (5% by default), the key is parked until its reset time.

⏱

Smart cooldowns

Cooldowns follow retry-after and rate-limit reset times. Dead keys back off exponentially, and an honest 429 with retry-after is returned only when every key is out.

🎯

Per-key caps

Optional daily token and USD caps per key. A key that reaches its cap leaves the rotation until midnight UTC.

🧩

Mix providers

Anthropic API keys and Bedrock API keys (Mantle or Runtime, any region) in one pool. Bedrock can be the safety net when Anthropic is busy, or the other way round.

📊

Per-key analytics

Requests, tokens, cost, failovers, live sessions and remaining rate limit per key, plus a "by upstream key" breakdown on the dashboard.

🔐

Encrypted at rest

AES-256-GCM with KEY_POOL_SECRET. Keys are tested on save, shown only as their last four characters, and never logged.

🧾

Config as code

Manage keys in the console, or ship them read-only with PROVIDER_KEYS_JSON from Secrets Manager.

👥

Team key groups

Reserve keys for teams. A team uses its own keys first and overflows to shared keys; other teams never see them.

⏲

Bedrock quotas

Enter a key's tokens and requests per minute. The gateway tracks a sliding minute and parks the key just before throttling.

🌐

Multi-task safe

Cooldowns are shared between gateway tasks and survive restarts. Rendezvous hashing puts a session on the same key on every task.

Limits apply per Anthropic organization and per AWS account and region. Keys from the same org share one limit; keys from separate orgs or accounts add up.

Cost control

🔌

Zero install

Two lines in ~/.claude/settings.json. Developers need no AWS credentials.

🧠

Request-class routing

Sends subagent, auxiliary and compaction traffic to its own model, such as Sonnet or Haiku.

🎚

Effort control

fill sets a default effort when a request has none. override always sets it.

✂️

Tool-output trimming

Shortens huge tool_result text but keeps its head and tail.

🧷

Bedrock bridging

Strips beta fields and headers that Bedrock rejects, so you avoid 400 Extra inputs are not permitted.

💸

Budgets & token limits

Daily per-developer limits with warn, downgrade or block, reported in response headers.

📚

Live model catalog

Builds /v1/models live from Bedrock, so /model just works.

📊

Observability

CloudWatch EMF metrics, a dashboard and alarms, plus an in-app dashboard with a 14-day trend.

🔐

Privacy by design

Conversation content is never stored. Tokens are kept only as hashes, and logs contain numbers only.

🙋

Developer self-service

GET /v1/me with a personal token returns today's spend, tokens, cache hit rate and limits. No admin access needed.

🧾

Audit trail

Every admin action is logged: developers, policy, prices and key changes, never secrets.

🔀

Two Bedrock APIs

Mantle (Messages API) or Runtime (InvokeModel), switchable live, per policy, per developer or per key.

Operations new in v0.3

⚡

One-command deploy

install.sh sets up Docker, Caddy with automatic HTTPS and fresh secrets on any Linux server. Multi-arch images on ghcr.io/uurtech/tokener.

🔔

Alerts

Slack, Discord, Microsoft Teams or any JSON webhook. Key failures, pool exhaustion, recoveries and developer limits, throttled so nobody gets flooded.

🔑

Admin SSO

Sign in with Google Workspace, Okta, Entra ID, Auth0 or Keycloak (OpenID Connect + PKCE), limited to your domains. Every admin action carries the person's e-mail.

📆

Monthly budgets

Monthly USD and token caps per developer, next to the daily ones, with warning headers at 80%.

🙋

Developer page

Developers open /me with their own token to see today's and this month's spend, limits with reset times and a 14-day trend.

🗝

KMS encryption

On AWS, pool keys are sealed under a KMS data key. Revoke one IAM permission and every stored key is unreadable; every unseal is in CloudTrail.

Marketplace-ready

A hardened CloudFormation template for production: HTTPS only, private subnets, admin console restricted to listed CIDRs, admin token in Secrets Manager, and RegisterUsage metering.

cd infra && npm ci && npm run synth:marketplace
# → dist/tokener-marketplace.template.json

Recommended rollout order

Start in measurement mode for a week with every policy off and bridging on. Then enable one lever at a time.

  1. Auxiliary → Haiku. Titles and summaries move to the cheapest model.
  2. Subagent → Sonnet. Subagent work runs on a cheaper model than the main loop.
  3. tool_result trimming. 20,000 characters is a good threshold.
  4. Effort. Try EFFORT_MODE=fill with DEFAULT_EFFORT=high.
  5. Budget downgrade. New conversations start on a cheaper model once a limit is reached.
